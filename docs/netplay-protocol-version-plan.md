# 联网协议的版本与兼容方案（第 2 稿，按审阅意见修订）

> 需求：协议会随 APP 升级演进 → 需要**版本号 + 兼容规则**；不兼容的客户端**拒绝联网对战**（含手工建服务器/直连 IP）；发布时两端同步。
> 本文只出方案，未改任何代码。审阅确认后再实现。
> 相关：[netplay-state-sync-plan.md](netplay-state-sync-plan.md)、[netplay-control-plan.md](netplay-control-plan.md)

## 0. 本稿相对第 1 稿的修订（按审阅意见）

| 审阅意见 | 本稿做法 |
|---|---|
| ① 不区分主次版本，不兼容就提升版本号；兼容则不变 | 取消 MAJOR/MINOR，改为**单一整数版本号**（§1、§2） |
| ② 显示搜索到的游戏版本号，不同版本不能连接 | 发现层 beacon 带 `net_ver`、房间列表加"版本"列，不同版本不可选（§5）；握手兜底拒绝（§4） |
| ③ 缓存帧数双方必须一致，由主机提供，不能用本地默认值 | 客户端**必须**采用服务端下发的 `cache_num`，缺失/越界 → 拒绝连接（§6） |
| ④ 读档失败（任一方加载不成功）→ 硬件复位，不中断连接 | 见 [netplay-state-sync-plan.md](netplay-state-sync-plan.md) §7 |
| 附带影响：版本必须相同 → 能力集必然相同 | **取消 caps 能力位**（冗余），读档等能力不再单独协商（§2 备注） |

## 1. 版本号定义

```c
#define  NET_VER   2      // 单一整数: 不兼容修改时 +1, 兼容修改保持不变
```

- **单一整数、单调递增**，不区分主次。比较规则只有一条：**相等才允许连接**，不等一律拒绝。
- 当前代码里的 `NET_VER = 0x0101`（`comm/net.h:66`）语义不明，建议**重新编号为 1 起步**（待确认，见 §9）。
- 发现层 `LAN_VER`（`comm/lan.h`）**独立编号、独立判定**：它只管"看不看得见房间"，与对战协议版本解耦；往 beacon 的 pad 区加只读展示字段属于**兼容修改，不改 `LAN_VER`**（§2）。

## 2. 兼容判定规则

判定一句话：**只要旧端"按原逻辑还能正常对战"，就是兼容；否则就是不兼容（版本号 +1）。**

| 变更类型 | 例子 | 判定 | 版本号 |
|---|---|---|---|
| 新增**需要两端同时理解**的命令 | `NET_CMD_QUIT`、`NET_CMD_STATE_*` | **不兼容** | **+1** |
| 改已有命令语义 / 命令字复用 | — | **不兼容** | **+1** |
| 改包长度 / 改字段语义 / 改字节序 | 给 `START_RSP` 加字段 | **不兼容** | **+1** |
| 改握手流程、必答顺序、校验规则 | 拒绝条件新增 | **不兼容** | **+1** |
| 改延迟线语义、主副手柄路由、缓存帧数协商方式 | §6 的强制下发 | **不兼容** | **+1** |
| 复用**闲置位**且旧端读 0 也能继续 | `START_RSP.fno` 高 32 位 = `cache_num` | 兼容 | 不变 |
| beacon **pad 区**新增只读展示字段（`net_ver`） | §5 | 兼容 | 不变（`LAN_VER` 也不变） |
| 纯本地实现/UI 文案/日志 | — | 兼容 | 不变 |

**实践建议（简化判断）**：联网协议相关的功能改动，**一律 +1**。真正"兼容"的只有两类——纯本地改动，和"旧端读到 0 也能照常对战"的闲置位/beacon 展示字段。宁可多升一个版本号，也不要出现"版本号相同但连上了却行为不同"。

> 备注：第 1 稿的 **caps 能力位取消**。既然版本号必须相同才允许连接，两端的能力集必然相同，caps 是冗余的。第 1 稿想解决的"对端不支持读档"问题，现在由"版本号不同 → 不能连接"直接覆盖。

## 3. 版本号在哪里交换

| 通道 | 字段 | 现状 | 本方案 |
|---|---|---|---|
| TCP 握手 | `NET_CMD_START.ver` | 已有 | 不变；客户端**也要判**（现状只有服务端判） |
| TCP 握手 | `NET_CMD_START_RSP.fno` | 成功时高 32 位 = `cache_num`，低 32 位/失败时全空闲 | **失败时 `fno` = 服务端 `NET_VER`**，让客户端能显示"本机 x / 对端 y" |
| 局域网发现 | beacon `pad[10]` | 全 0 | 取 4 字节放 `net_ver`（网络序），`pad` 缩到 6；**报文仍定长 128B** |

不新增包、不改包长 —— 与项目已有的"`fno` 高 32 位复用为 `cache_num`"做法一致。

## 4. 握手校验与拒绝（覆盖手工建服务器与快速配对）

```
客户端: START(ver=NET_VER, crc32)
服务端: ver   不等 -> START_RSP(code=1, fno=服务端NET_VER)   失败路径 fno 空闲, 回传版本
        crc32 不等 -> START_RSP(code=2)
        cache 非法 -> START_RSP(code=3)   (见 §6)
        通过      -> START_RSP(code=0, is_ntsc, fno高32=cache_num)
客户端: code=1 -> "版本不一致（本机 2 / 对端 1），请升级到相同版本后再联机"
        code=0 -> 采用服务端 cache_num(§6), 进入对战
```

- **两端都要判**：服务端判 `START.ver`；客户端拿到 `code=1` 时读 `rsp.fno` 显示对端版本，并在日志里记下双方版本号。
- 手工建服务器走的是同一套 `np_begin`/`np_poll`（`win32/dlgNetPlay.c:233`、`mac/iNESNetPlayDialog.m:316`），所以**自动覆盖**，不需要额外分支。
- 保留 5 秒握手超时兜底（`NP_HANDSHAKE_TIMEOUT`）。
- 提示文案两端统一，且**带上具体版本号**，方便用户报障。

## 5. 发现层（局域网快速配对）

- beacon `pad[10]` → `net_ver`(4) + `pad[6]`；`lan_room_t` 增加 `net_ver`。
- `LAN_VER` **保持 1 不变**（pad 区是兼容扩展，旧端忽略即可）。旧端看到新房间（LAN_VER 相同）会照常显示，但新端加入时走 TCP 握手兜底拒绝。
- 房间列表新增**"版本"列**：
  - 显示 `net_ver` 数字；读到 0（旧版 beacon 不填）→ 显示"旧版"；
  - **与本机版本不同 → 该行不可选（灰显）**，提示"版本不一致，需升级到相同版本"；
  - 列宽建议：mac `nick 118 / ROM 190 / 版本 52 / 缓冲 56`；win32 相应压缩 ROM 列（待定）。
- 手工建服务器没有发现层，靠 §4 的握手拒绝，行为一致。

## 6. 缓存帧数：必须一致，由主机下发（已拍板 + 已实现）

- **来源**：房主（服务端）的缓冲帧数一律从 `config.ini` 的 `[netplay] cache_num` 读取（没有该项则用 `NP_CACHE_DEFAULT` = 4，越界夹到 `NP_CACHE_MIN..NP_CACHE_MAX`）。**包括手工建服务器 / 直连模式** —— 不再由下拉框或常量决定；后续在"设置"里提供修改入口。
- **下发**：服务端在 `START_RSP.fno` 高 32 位下发自己的 `cache_num`。
- **采用**：客户端（加入方）**必须**采用服务端的值；**禁止**回落到本地默认（`comm/npsession.c` 里"读到 0 或越界就保留本地默认值"的分支已删除）。
- **拒绝**：读到 0（旧版未携带）或越界 → 拒绝连接，提示"对端版本过旧（未下发缓冲帧数），请升级到相同版本！"。不新增 `code`，直接走 `NP_POLL_FAILED`。
- **发现层**：`cache_num=0`（旧版）与"版本不同"同等对待 → 不可选。
- **UI（2026-09-19 拍板：两端保持一致）**：**两端都不再提供缓冲帧数下拉框** —— mac 已取消（房间大厅与联网对话框），win32 的「联网对战…」`IDC_CMB_CACHE` 与局域网面板 `IDC_LANMATCH_CMB_CACHE` 一并取消，改为只读文本显示当前值（如"缓冲 4 帧（config.ini [netplay] cache_num）"）。唯一来源就是 `config.ini`，发布后不可改；后续在"设置"里提供修改入口。
- 这条属于**不兼容修改**（改变了协商失败时的行为）→ `NET_VER` +1。
- 实现位置：`comm/npsession.c`（握手）、`mac/iNESLanLobby.m` / `mac/iNESNetPlayDialog.m`（`GetConfigInt`）、`win32/dlgNetPlay.c` / `win32/dlgLanMatch.c`。

## 7. 发布流程（checklist）

1. 判定级别（§2）：本次改动兼容还是不兼容。**拿不准就按不兼容处理。**
2. 不兼容 → `NET_VER += 1`（`comm/net.h`）；改到 beacon 字段才动 `LAN_VER`（本方案不动）。
3. 更新本文 §8 的**版本变更表**。
4. 两端（win32 / mac）**同版本一起发布**；发布说明写"联网协议版本 N，两端必须一致"。
5. 启动时日志打印：`netplay: proto=2`（排障用）。
6. 冒烟：同版本可连；异版本按预期拒绝（面板灰显 + 握手提示）；`cache_num` 缺失时拒绝。

## 8. 版本变更表

| 版本 | 变更 | 判定 |
|---|---|---|
| **1** | 基线：START / START_RSP / FRAME / CHAT / **QUIT**；`START_RSP.fno` 高 32 位 = `cache_num`（旧端读 0 用默认值） | —（重新编号，对应原 `0x0101`） |
| **2（当前）** | **状态载入 `STATE_*`**；**缓冲帧数强制由主机下发**（缺失/越界拒绝）；握手失败回传服务端版本；发现层 beacon 带 `net_ver` + 列表显示版本、异版本不可选 | **不兼容，+1** |
| 3（后续按需） | … | 每次不兼容改动 +1 |

> 说明：`NET_CMD_QUIT` 在两端都已存在（本次改动前就有），因此归入基线 1；本轮的 `STATE_*` 等改动把版本号推到 2。规则仍是"版本号相同 = 行为一定相同"。

## 9. 拍板结果（第 2 稿审阅后已定，且已实现）

1. **版本号从 1 重新编号** → 基线 `NET_VER = 1`，本轮升到 **2**（`comm/net.h`）。
2. 版本不一致 → **不可连接**：发现层列表灰显 + 提示"协议版本不一致，请升级到相同版本后再联机。"；手工建服务器/直连由握手拒绝，提示"版本不一致（本机 2 / 对端 1），请升级到相同版本！"。
3. 旧版房间（`net_ver=0`）与"版本不同"同等对待 → 不可选。
4. 缓冲帧数从 `config.ini` 的 `[netplay] cache_num` 读取（无配置默认 4），**手工建服务器 / 直连模式同样**；客户端强制采用主机下发的值（见 §6）。**两端 UI 保持一致：都不提供缓冲帧数下拉框**（win32 的两个下拉框取消，只作只读显示）。
5. 读档仅主机发起；**存档（保存状态）双方均可**（两个前端都只在"已载入 ROM"时限制，联网时不额外禁用）。
6. 状态载入失败的复位范围：见 [netplay-state-sync-plan.md](netplay-state-sync-plan.md) §7 / §12。
